# AGENTS.md — PC Maintenance Kit

Guidance for AI coding agents working in this repository.

## What this is

A gamer-focused Windows 10/11 maintenance toolkit written entirely in **Windows PowerShell 5.1+**.
It ships as a dark tabbed WinForms GUI plus a CLI mode, and covers cleanup, gaming tweaks,
controlled Windows Update / winget runs, and optional DISM/SFC repair. Distributed as a signed
(optionally) ZIP release and via a one-line `irm | iex` installer.

No Node/npm, no build toolchain, no package manager — this is not a DSH/web project. Do not
treat it as one.

## Conventions

- **PowerShell 5.1 compatible** — every script starts `#Requires -Version 5.1`. Do not use
  PowerShell 7-only syntax (e.g. ternary `?:`, `??`, pipeline chain operators).
- **Windows-only.** Assume `Test-Path`, WinForms, WMI/CIM, registry access, etc. are all fair game.
- Functions use PowerShell's approved verb-noun naming (`Get-`, `Invoke-`, `Apply-` is used loosely
  here for existing code — match existing style in the file you're editing rather than introducing
  a new one).
- Safety-first defaults matter to this project's purpose: Windows Update and winget are **off by
  default** in "Weekly Full" mode; destructive/slow actions (launcher cache cleanup, Repair/DISM/SFC)
  require explicit confirmation. Preserve these defaults unless the user explicitly asks to change them.
- `VERSION` is the single source of truth. `Get-KitVersion` in `lib\Extras.ps1` sets
  `$Script:AppVersion` from that file. The test suite asserts they match. README examples
  should use the same version.
- `dist\PC-Maintenance-Kit-v*\` staged folders and `dist\*.zip` / `.zip.sha256` are build artifacts
  regenerated by `Build-Release.ps1`. Don't manually patch files inside `dist\`; change the source
  in the repo root / `lib\` and rebuild.

## Running things

From the repo root, in Windows PowerShell:

```powershell
# GUI (default)
powershell -NoProfile -ExecutionPolicy Bypass -File .\PC-Maintenance.ps1 -Mode Gui

# CLI menu
powershell -NoProfile -ExecutionPolicy Bypass -File .\PC-Maintenance.ps1 -Mode Cli

# Non-interactive modes
powershell -NoProfile -ExecutionPolicy Bypass -File .\PC-Maintenance.ps1 -Mode Full
powershell -NoProfile -ExecutionPolicy Bypass -File .\PC-Maintenance.ps1 -Mode CleanupOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\PC-Maintenance.ps1 -Mode UpdatesOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\PC-Maintenance.ps1 -Mode Repair
powershell -NoProfile -ExecutionPolicy Bypass -File .\PC-Maintenance.ps1 -Mode FullRepair
powershell -NoProfile -ExecutionPolicy Bypass -File .\PC-Maintenance.ps1 -Mode Scheduled
```

The script self-elevates to Administrator (`Ensure-Admin`) — expect a UAC prompt when actually
running it, not just parsing/linting it.

## Tests

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\PathHelpers.Tests.ps1
```

This is the **entire** test suite (no Pester). It dot-sources the `lib\*.ps1` files directly and
asserts with a hand-rolled `Assert-True`. It exits `1` on any failure (CI treats non-zero as
failure). Coverage includes:

- `Join-PathSafe` / `Test-PathSafe` behavior, including missing-drive edge cases that must not throw
- `Get-SteamDownloadingPaths` doesn't throw
- Default GUI settings (`HomeWU`/`HomeWinget` default `false`) and settings path under `%LOCALAPPDATA%`
- `$Script:AppVersion` matches the `VERSION` file (read automatically — no literal to update)
- `Apply-ModeFlags Full` leaves Windows Update / winget off but enables cleanup
- `Get-DeviceSummary` doesn't throw, returns CPU info, and is cached (same object on repeat calls)
- **Cleanup path safety** — `Test-SafeCleanupPath` rejects empty paths, drive roots, `%USERPROFILE%`,
  `%SystemRoot%`, Program Files, and `C:\Users`; `Remove-OldFilesInPath` refuses them and returns 0
- **Behavioral cleanup test** — a real temp tree is created, cleaned, and asserted
- **Settings round-trip** — save/load preserves values and unknown forward-compat keys
- Gaming Optimization Score shape, weights summing to 1.0, and grade thresholds
- **Every top-level script and lib file parses cleanly** via
  `[System.Management.Automation.Language.Parser]::ParseFile` — the `lib\` list is discovered from
  disk, so a new lib file is syntax-checked automatically
- SHA256 checksum line formatting

Run this after touching any `lib\*.ps1` file or the entry script. There is no linter configured —
the parse check above is the closest thing to one, so a syntax error will fail tests, not just CI.

## Release build

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Build-Release.ps1 -Version 5.4.2
```

Produces `dist\PC-Maintenance-Kit-v5.4.2.zip` and `.zip.sha256`. Optional signing:

```powershell
.\Build-Release.ps1 -Version 5.4.2 -CertThumbprint 'THUMBPRINT'
# or
.\Build-Release.ps1 -Version 5.4.2 -PfxPath 'C:\certs\pcmk.pfx' -PfxPassword 'your-password'
```

CI (`.github\workflows\ci.yml`) runs the test suite, then runs `Build-Release.ps1` (using
`PCMK_SIGN_PFX_BASE64` / `PCMK_SIGN_PFX_PASSWORD` secrets if present) and verifies the resulting
ZIP's SHA256 against the generated `.sha256` file.

## When making changes

1. Bump `VERSION` (and the fallback in `lib\Extras.ps1` `Get-KitVersion`), the matching assertion in
   `tests\PathHelpers.Tests.ps1` (reads VERSION automatically), the default `-Version` in `Build-Release.ps1`, and version
   references in `README.md` together — they're expected to move in lockstep.
2. Run `tests\PathHelpers.Tests.ps1` before considering a change done.
3. If you add a new root-level script that should ship in releases, add it to `Build-Release.ps1`'s
   required payload list. New `lib\*.ps1` files ship and get parse-checked automatically.
4. Keep `Get.ps1` short, readable, and non-obfuscated — it's meant to be safely eyeballed by a user
   before piping into `iex`.
5. Don't hand-edit anything under `dist\`; it's generated output.
